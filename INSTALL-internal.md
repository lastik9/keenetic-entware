# INSTALL-internal — OPKG Entware во внутреннюю память (без USB)

Альтернатива USB-пути (`prepare.ps1`/`prepare-linux.sh`). Здесь **не нужны ни ПК, ни флешка, ни
WSL/usbipd** — установка идёт целиком на роутере через веб-интерфейс или CLI. Подходит не всем
моделям и не под любую нагрузку — см. раздел 0.

> Когда что выбирать:
> - **Внутрь (этот документ)** — модель поддерживает, набор лёгкий (AdGuard, простые пакеты), хочется без торчащей флешки.
> - **USB (`prepare.ps1`)** — нужен объём, swap, тяжёлые пакеты (например mihomo с гео-базами), или модель внутреннюю установку не умеет.

---

## 0. Подходит ли это вам (проверить ДО начала)

Внутренняя установка — **штатная фича Keenetic с KeeneticOS 3.7+**, но только для части моделей
(Entware пишется в раздел UBIFS внутренней NAND-памяти). Три условия:

1. **Модель в списке поддержки.** По официальной статье Keenetic это, в частности:
   KN-1010/1011, KN-1810/1811, KN-1910, KN-2010, KN-2110, KN-2310, KN-2410, KN-2510, KN-2610,
   KN-2710, KN-3810, KN-3610 (на 3.7+), а также новые aarch64-модели (Hopper/Hero и т.п.).
   Актуальный список — в статье Keenetic «Установка OPKG Entware на встроенную память роутера».
   Ориентируйся на номер **`KN-xxxx` с наклейки**, а не на маркетинговое имя.
   Если модели в списке нет (например, Extra KN-1710/1711) — внутренняя установка недоступна,
   иди по USB-пути.
2. **KeeneticOS 3.7 или новее.** Обнови прошивку до актуальной.
3. **Набор пакетов лёгкий.** Внутренний раздел маленький (см. раздел 5). Тяжёлое сюда не влезет.

## 1. Определить архитектуру

Арку задаёт точный номер модели, не имя. По официальной статье Keenetic:

| арка | модели (примеры) |
|---|---|
| **mipsel** | KN-1010/1011, KN-1810, KN-1910, KN-2310, KN-3810, KN-2610 |
| **mips** | KN-2410, KN-2510, KN-2010, KN-3610, KN-2110 |
| **aarch64** | новые модели (Hopper/Hero и др.) |

Не уверены в арке — не угадывать: посмотреть в статье Keenetic по своему `KN-xxxx`.

## 2. Установка через веб-интерфейс (рекомендуется)

Самый надёжный способ: роутер сам скачает installer нужной арки, руками URL подставлять не надо.

1. **Общие настройки → Обновления и компоненты → Изменить набор** → включить компонент
   **«Поддержка открытых пакетов (OPKG)»**. Драйверы ext-файловой системы для внутренней установки
   **не нужны** (пишем в UBIFS, а не в ext4). Сохранить, дать роутеру перезагрузиться.
2. Открыть страницу **OPKG** (Приложения → OPKG).
3. В поле **«Накопитель»** выбрать **«Внутренняя память»** (Internal storage).
4. Убедиться, что для аккаунта включён доступ к OPKG-сервисам. **Сохранить.**

Роутер развернёт Entware во внутренний раздел. Перейти к разделу 4.

## 3. Установка через CLI (альтернатива)

Если веб-путь по какой-то причине не сработал. По SSH (root, порт **222**):

```
opkg disk storage:/ <URL-инсталлера-под-вашу-арку>
```

Где `storage:/` — системный (внутренний) раздел. URL инсталлера **брать под свою арку из
официальной статьи Keenetic / с bin.entware.net**, не по памяти. Примеры формата (сверить перед
использованием):

- aarch64: `https://bin.entware.net/aarch64-k3.10/installer/aarch64-installer.tar.gz`
- mipsel:  `https://bin.entware.net/mipselsf-k3.4/installer/mipsel-installer.tar.gz`
- mips:    URL уточнить в статье Keenetic под свою модель.

> Дисциплина «земля важнее памяти»: точный путь инсталлера сверяй с официальным источником —
> не подставляй по догадке, иначе установка не встанет или подтянет не ту арку.

## 4. После установки

**Первым делом — смени дефолтный пароль.** После установки Entware во внутреннюю память SSH
поднимается с логином `root` и паролем `keenetic` (порт 222). Сразу поменяй:

```
passwd root
```

Внутренняя память — **лёгкий профиль**. Базовые пакеты для HTTPS:

```
opkg update && opkg install ca-bundle ca-certificates
```

Дальше ставь **только нужные лёгкие пакеты** вручную (`opkg install <пакет>`), держась раздела 5.

**`router-setup.sh` сюда не входит — и это нормально.** Он часть **USB-пути**: его задача — swap +
XKeen/mihomo, а место им на USB, где есть объём и swap. На внутренней памяти его полный режим (пункт
1 меню) и «Только XKeen» (пункт 2) **не запускай** — они тянут тяжёлый mihomo на NAND (раздел 5).
Единственный его пункт, применимый и на внутренней памяти, — **фикс SSH-222** (пункт 4: протухший
pid-файл dropbear), он не USB-специфичен. Остальное — для USB.

> Короче: на внутреннем пути от нашего репо тебе нужны не скрипты, а этот документ + `TROUBLESHOOTING.md`
> (SSH-222, сертификаты, whitelist installer) + дисциплина «модель→арка, сверяй installer».
> Тяжёлый тулинг (`prepare.*`, полный `router-setup.sh`) остаётся на USB-пути.

## 5. Ограничения внутренней установки (важно)

Наши USB-грабли (WSL/usbipd/формат флешки) тут исчезают, но появляются **другие**, которых на
USB не было:

- **Износ NAND.** Внутренняя flash имеет ограниченный ресурс записи. Keenetic прямо предупреждает
  сначала разобраться в особенностях NAND, чтобы не повредить её.
- **Swap на NAND делать НЕЛЬЗЯ.** В USB-флоу мы создаём swap-раздел; здесь swap на внутренней
  памяти противопоказан (быстрый износ). Если swap реально нужен — только zram (в ОЗУ) или USB.
- **Мало места.** Внутренний раздел маленький. Хватит на лёгкий набор; тяжёлое (mihomo с
  geoip/geosite/mmdb, большие кэши, объёмные логи) — впритык и вредно для NAND. Для такого — USB.
- **UBIFS штатно не тестируется самим Keenetic.** В логе установки роутер прямо пишет: если
  что-то пойдёт не так — использовать ext2/3/4 (то есть USB). При странном поведении внутренней
  установки не бороться, а уходить на USB-путь.

Если упёрлись в нехватку места — не «доливать» на внутреннюю, а переносить OPKG на USB.

## 6. Бэкап (вместо `backup-linux.sh`)

`backup-linux.sh` делает бит-в-бит образ ext4-флешки и для внутренней установки **не подходит**.
Здесь бэкап проще — заархивировать каталог `/opt` на самом роутере и забрать файл к себе:

```
tar czf /tmp/opt-backup.tgz -C /opt .
```
Затем скопировать `/tmp/opt-backup.tgz` по SCP/SFTP (root, порт 222).

---

## 7. Удаление (если понадобится)

По CLI роутера (не в busybox-shell, а в конфигурационном режиме):

```
no opkg disk                 # отключить автозапуск OPKG
no system mount storage:     # отмонтировать системный раздел
erase storage:               # стереть содержимое внутреннего раздела
```

## Граница

`router-setup.sh` — наш код, работает как есть. Установка Entware во внутреннюю память —
штатный механизм Keenetic; за его поведение и список поддерживаемых моделей отвечает Keenetic,
актуальную информацию сверяй в их официальной статье. mihomo и прочий сторонний софт — вне
периметра проекта.
