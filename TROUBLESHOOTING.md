# TROUBLESHOOTING

Свод типичных проблем при подготовке USB-флешки под Entware (`prepare.ps1` / `prepare-linux.sh`)
и первичной настройке роутера. Большинство пунктов — **операторское трение и внешние факторы**
(порт, провайдер, ребут WSL), а не баги скрипта. Формат: симптом → причина → лечение.

Пин проверенной версии: `main` @ `9e2116eb9da584e4fbad71041484c50fac3a2f46`.
Всегда сверяй sha256 скачанных файлов до запуска (см. README).

## Флешка

### `USB-накопители не найдены`, хотя флешка вставлена
**Причина.** Плохой контакт/порт или Windows ещё не поднял носитель как диск. `prepare.ps1`
фильтрует устройства по `BusType -eq USB`; пока система не смонтировала флешку как накопитель,
скрипт её не видит. Это не баг скрипта.

**Лечение.** Передёрнуть флешку в **другой порт — прямой на корпусе, без хаба**, подождать ~5 секунд,
повторить. Проверить видимость вручную:
```powershell
Get-CimInstance Win32_DiskDrive | ft Index,Model,InterfaceType,MediaType,Size
```

### Прерванный прогон — следующий старт «не видит» флешку
**Причина.** Прерванный запуск оставляет висящую привязку `usbipd` (флешка «уехала» в WSL и не
вернулась в Windows).

**Лечение.** Посмотреть и снять привязку:
```powershell
usbipd list
usbipd detach --busid <BUSID>
usbipd unbind  --busid <BUSID>
```

## WSL2

### Чистая Windows 10: WSL не ставится «с нуля»
**Причина.** Inbox-`wsl.exe` — заглушка без движка; `wsl --update` печатает справку вместо установки.

**Лечение.** В коде решено (`Enable-WindowsOptionalFeature` + ребут). Оператору: **если скрипт
просит перезагрузку — перезагрузиться и запустить `prepare.ps1` снова.** Это штатный шаг, не ошибка.

### Повторный `wsl --install` роняет CBS (`COMException`)
**Причина.** Ручной повторный вызов установки конфликтует с обслуживанием компонентов.

**Лечение.** Не дёргать `wsl --install` вручную. Лечится ребутом и:
```powershell
DISM /Online /Cleanup-Image /RestoreHealth
```

## usbipd

### На чистой Win10 usbipd ставится только из MSI
**Причина.** `winget` отсутствует на свежей системе.

**Лечение.** Скрипт ставит MSI сам. После установки желателен ребут.

### Свежий usbipd не работает до ребута (`service not running`)
**Причина.** Служба usbipd не поднялась в текущей сессии.

**Лечение.** Скрипт это ловит и просит перезагрузку — **перезагрузиться и запустить снова.**

### Ручной usbipd вне скрипта
Если делаешь bind/attach руками (диагностика), нужно **два** условия:
1. права администратора (bind/attach);
2. **живой WSL-держатель** в отдельном окне — разовые `wsl -- cmd` дистрибутив не удерживают:
```powershell
wsl -d Ubuntu -u root -- sleep 1800
```

## Сеть / установщик Entware

### Ложный «интернет есть», но installer не качается
**Причина.** SNI-whitelist или фильтрация провайдера режет хосты Entware.

**Лечение.** Добавить в whitelist:
- `bin.entware.net`
- `yacloud.entware.net`
- IP `158.160.45.54`

## Логирование и запуск

- **Не запускать `prepare.ps1` через `| Tee-Object`** — ломает UTF-8. Для лога использовать
  `Start-Transcript`. Помни: скрипт **самоподнимается через UAC в НОВОЕ окно**, поэтому транскрипт
  исходного окна будет пустым — логировать нужно тот процесс, что реально выполняет работу.
- **`-UseMinimalHeader` недоступен в PowerShell 5.1** — не использовать.

## Ручная диагностика в WSL

- **PowerShell рвёт длинные bash-однострочники** по `|` и `$( )` даже в кавычках. При ручной
  диагностике давай команды без пайпов либо заворачивай bash целиком в одинарные кавычки.
- **Чтение features раздела флешки:** читать `dumpe2fs` целиком, не через обёртку с пайпом:
  ```
  wsl -d Ubuntu -u root -- dumpe2fs -h /dev/sdX2
  ```
  `debugfs -R "..."` в PowerShell-обёртке может давать ложное `Filesystem not open` — не пугаться,
  это артефакт обёртки, а не повреждение ФС.

### `orphan_file` в выводе ext4
Появление фичи `orphan_file` зависит от `mke2fs.conf` конкретной сборки e2fsprogs хоста
(в одних окружениях есть, в других нет) — то есть ext4-вывод недетерминирован по машине.
**На совместимость это не влияет:** проверено, что раздел с `orphan_file` монтируется RW без ошибок
на ядре роутера (mipsel-3.4). Отдельного действия не требует.

## Сторонний софт (вне периметра проекта)

Ниже — не про наш код, а про часто идущий следом XKeen. Оставлено как справка.

- **XKeen `invalid domain`** — убрать мид-лейбл `*` из шаблона: писать `+.3gppnetwork.org`,
  а не `+.*.3gppnetwork.org`.
- **XKeen `all proxies timeout`** при ручном пинге десятков нод на слабом CPU (напр. MT7621) —
  не поломка. Автотест с `interval:30` поднимает рабочие ноды сам.

## Безопасность

- **Сменить пароль WSL** после настройки: `passwd`. Пароль, введённый при первичной установке
  Ubuntu, мог засветиться в логах/переписке.

## Что делать дальше на роутере

Веб-интерфейс → Общие настройки → включить «Поддержка открытых пакетов (OPKG)» +
«Файловая система Ext» → страница OPKG → выбрать накопитель «OPKG» → Сохранить.
Затем по SSH (root, порт 222):
```
opkg update && opkg install wget-ssl ca-bundle ca-certificates
wget -T 15 -t 3 -qO- https://raw.githubusercontent.com/lastik9/keenetic-entware/main/router-setup.sh | sh
```
